# 實驗計畫：VACE 外觀 LoRA（Goal Force 負責動作，記憶負責外觀）

建立日期：2026-11-25。執行紀錄寫在本檔最後的「執行紀錄」。

## 1. 目標
**分工原則：** 動作和物理行為（位置、移動、倒下、姿勢）交給 Goal Force；外觀（顏色、花紋、文字、身分）交給記憶。

夜間實驗（`reports/overnight_2026-11-25.md`）發現兩個問題：
- **修補模型 VACE 1.3B 不會「只修外觀」。** 拿原圖當參考時，會連姿勢一起抄（達摩被拉回坐正、水壺多出直立分身、白球變紅）；保留目前像素時又修不好（色斑、碎裂，外觀分數從 0.71 掉到 0.57）。
- **完整方法的狀態規則在和 Goal Force 搶物理的決定權**，造成殘影杯子、立著不倒的骨牌。

**本實驗：** 在 VACE 1.3B 上訓練一個 LoRA，教它「照參考圖修外觀，但姿勢和位置完全照輸入影片」。訓練後的修補流程**不再使用狀態規則**。

**不在範圍內：** Goal Force 本身的物理錯誤（骨牌融成一塊、物件消失、憑空多出物件）。這類回合之後交給「驗收器」偵測並換 seed 重新生成，不靠修補。

## 2. 模型與訓練方式
| 項目 | 設定 |
|---|---|
| 基礎模型 | Wan2.1-VACE-1.3B（含 DiT 主幹與 VACE 分支）、T5 文字編碼器、Wan2.1 VAE，全部凍結 |
| 可訓練參數 | LoRA，加在 DiT 和 VACE 分支的注意力與前饋層（`q,k,v,o,ffn.0,ffn.2`），rank 32 |
| 損失函數 | DiffSynth 內建的 flow matching 損失（`WanVideoPipeline.training_loss`） |
| 程式 | `multiturn/lora_data.py`（資料）、`multiturn/train_vace_lora.py`（訓練）、`multiturn/lora_eval.py`（評估） |
| 環境 | `venv/`（torch 2.11、DiffSynth、peft 0.22），不安裝新套件 |

## 3. 訓練資料（自動產生，不需人工標註）
每筆資料是一組「題目 → 答案」：

| | 內容 | 讓模型學到什麼 |
|---|---|---|
| **答案** | 一段乾淨的真實影片片段 | 還原的目標 |
| **輸入影片** | 同一段影片，但物件區域被**故意弄壞**：模糊、降解析度、色偏、局部塗灰、平滑掉細節、混入旁邊的像素（模擬融合）。**位置和姿勢不變**。前 4 格不弄壞，和實際修補時一樣 | 姿勢和位置要照輸入影片 |
| **參考圖** | 同一個物件在**另一個時間點**（至少相隔 15 格）的乾淨裁切，貼在 832×480 的白底上，有一半機率放在隨機位置、大小隨機縮放 0.8–1.2 倍 | 參考圖只用來看外觀，不能照抄姿勢和位置 |
| **mask** | 物件 mask 往外擴張 7–15 px | 要修哪裡 |
| **文字描述** | `a video of <影片類別>`，例如 `a video of bear` | 和推論時一樣有文字條件 |

**關鍵設計：** 參考圖的姿勢故意和答案不同。照抄參考圖姿勢的模型會答錯，所以它被迫學會「外觀看參考圖、姿勢看輸入影片」。

**資料來源：**
1. **DAVIS 2017 trainval 480p**（第一階段的主要資料）：train 集 60 支影片拿來訓練。val 集 30 支中，固定取 15 支當測試，不參與訓練。下載到 `datasets/davis/`，不進 git。
2. **同學拍的照片**（第二階段）：用 SAM2 切出物件、補好背景，再讓物件平移、旋轉、縮放、傾倒，做成 2D 動畫。答案是精確已知的，物件類型也和我們的場景接近。照片到了以後再加入，同一批照片會留一部分只當測試。
3. **Goal Force 第 1 回合中外觀還正常的片段**（可選）。

## 4. 訓練設定
| 項目 | 第一階段設定 |
|---|---|
| 片段長度、解析度 | 33 格、832×480（推論時是 81 格；只訓練較短片段以節省記憶體） |
| batch | 1 |
| 優化器 | AdamW，學習率 1e-4，權重衰減 0.01 |
| 步數 | 先跑 3,000 步 |
| 其他 | 梯度檢查點（gradient checkpointing）、bf16；文字特徵事先算好，之後把 T5 移出 GPU |
| 存檔 | 每 500 步存一次 LoRA，到 `outputs/lora/vace_appearance/step-<N>.safetensors` |
| 紀錄 | 每 10 步記錄 loss，寫到 `outputs/lora/vace_appearance/train_log.jsonl` |

**試跑：** 正式訓練前先跑約 20 步，確認流程、記憶體和每步時間；產生 4 筆訓練資料的預覽圖並親自檢查。

## 5. 評估
**測試一：DAVIS 測試影片（15 支，沒看過）**
- 同一組固定的破壞方式（固定亂數種子），33 格。
- 比較：原本的 VACE vs 訓練後的 VACE（step 1000、2000、3000），參考圖、mask、文字都相同。
- 指標，都只在物件區域內計算、對照乾淨答案：
  - **PSNR**：越高代表越接近答案；
  - **R-DINO**：物件裁切和答案裁切的相似度，越高代表外觀越對；
  - **姿勢保留**：修補後物件區域的輪廓和答案輪廓的 IoU，越高代表姿勢越沒被改掉。

**測試二：夜間實驗的影片**
- 新的修補條件 `lora`：保留目前像素（顏色往記憶校正），參考圖用上一回合最後一格的裁切，**沒有狀態規則**，LoRA 開啟。
- 對照條件 `nolora`：一樣的設定，但不開 LoRA，用來分離出 LoRA 本身的效果。
- 影片：#8 骨牌 12 支、洋芋片施力 3 支、咖啡、水壺、兩張書架、分支 C 和 D，共 20 支。
- 用同一支 `multiturn/evaluate.py` 評分，和夜間的 baseline、只有外觀記憶、完整方法放在同一張表和散佈圖上比較，並做目視稽核。

**測試三：同學的新照片**（照片到了以後）：當作完全沒看過的場景，也是 demo 候選。

**成功標準（事先定好）：**
1. 測試一：LoRA 的 PSNR 和 R-DINO 都高於原本的 VACE，姿勢保留 IoU 不比原本低。
2. 測試二：外觀分數（R-DINO 對最新狀態）高於 baseline 的 0.76（合計）或 0.71（骨牌），身分錯置 0 次，姿勢倒退的次數不比 baseline 多。

只達到 1、沒有達到 2，代表 LoRA 學會了修補，但沒辦法類推到 Goal Force 的走樣方式，下一步就要加入照片動畫和 Goal Force 片段。

## 6. 風險與對策
| 風險 | 對策 |
|---|---|
| DAVIS 是動物、人、車，和桌上物件差很多 | 第二階段加入同學照片做成的動畫 |
| 合成的破壞和 Goal Force 實際的走樣不像 | 破壞方式多樣化；以測試二為準 |
| 1.3B 修補模型的畫質上限 | 如實報告 LoRA 能改善多少 |
| 記憶體不夠（33 格） | 降成 25 格或 480×640 |
| 訓練不穩定或過擬合 | 每 500 步存檔，以測試一挑最好的步數 |

## 7. 時程
| 階段 | 內容 | 預估時間 |
|---|---|---|
| 0 | 下載 DAVIS、寫資料、訓練、評估程式，產生預覽圖檢查 | 半天 |
| 1 | 試跑 20 步 | 30 分鐘 |
| 2 | 正式訓練 3,000 步 | 3–6 小時 |
| 3 | 測試一、測試二 | 約 5 小時 |
| 4 | 寫結果報告（中文） | 1 小時 |
| 5 | 照片到了以後：加入照片動畫，再訓練一輪、跑測試三 | 另計 |

## 8. 規則
- 只用 `venv/` 和 `imagegen/venv/`，只在本專案資料夾內操作，所有快取放在資料夾內。
- 不刪除既有檔案，不改動夜間實驗的輸出；新結果放在 `outputs/lora/`。
- GPU 一次只跑一件工作。
